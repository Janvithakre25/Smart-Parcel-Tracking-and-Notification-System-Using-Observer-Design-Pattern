Observer Pattern Principles

The Observer Design Pattern defines a one-to-many dependency between objects so that when one object (the Subject) changes state, all its dependents (the Observers) are notified and updated automatically.

  • Loose Coupling: The Parcel only interacts with the generic Observer interface, not concrete classes.
  • Open/Closed Principle: New observers (e.g. WarehouseManager or SmsService) can be added without modifying Parcel.
  • Dynamic Subscription: Observers can be registered or removed at runtime via registerObserver() and removeObserver().

College Viva Defense: Why Is the Java Code Unchanged & What Are the Limitations?

1. Why the Java code was kept 100% untouched:

Academic evaluation strictly tests your understanding of pure Object-Oriented Design Patterns in fundamental Java without masking it behind enterprise web frameworks like Spring Boot or external database drivers. Keeping Main.java strictly unchanged ensures that the academic core logic is 100% verified and verifiable.

2. Why web UI buttons cannot alter the running Java instance without modifying Java code:

In Java, a standard public static void main(String[] args) program runs sequentially on the JVM from the first statement to the last statement and then immediately terminates (exit code 0). For a web browser to dynamically inject new customers or change statuses into the live JVM at runtime, the Java code would have to be modified to add a persistent socket server, an HTTP REST controller, or an IPC listener.

Because the strict project guidelines state: "Do not add any new Java methods, getters, setters, controllers, or services", any such modification would directly violate the strict rule. Therefore, the architectural solution is:

  • Real Java Integration Layer: An external Node.js runner executes the unaltered Main.java, captures its authentic stdout, and displays it in the terminal.
  • Client-Side Stepper: An interactive frontend simulator illustrates the dynamic runtime steps visually for viva presentation without modifying the immutable Java source code.
